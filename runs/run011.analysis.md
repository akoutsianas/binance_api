# run.011 analysis — GATE FAILED (vacuous); the fill-timing signal did not reproduce

*Analyzed 2026-08-16. Notebook: `runs/btc_lstm.run.011.ipynb` (causal maker/skip router). Executed on Colab, same 35-day w5 tar as run.010a.*

**TLDR:** run.011 built the maker/skip router that run.010a's Cell 10D branch pre-registered, under a strict causal/no-bias contract — and it failed **vacuously**: the val-EV search found no profitable threshold (best EV/trig = **+0.00 bps**), τ froze at 1.01, and the router routed **0 of 2,091** primary triggers (0% coverage, 10–11 abstain-days). That is the pre-registered "vacuous fail, not a tuned pass." But the more consequential result is upstream: **the fill-timing signal that fired the router branch did not survive.** up18's FAVOURABLE OOF AUC dropped from 0.610 (run.010a) to **0.518 (chance)** once the dn-side nan fix (pooled OOF) was applied, and the signal that remains is on the *dn* side (0.613) and carried by regime/time proxies, not microstructure. The ranking signal, meanwhile, is unchanged and still the strongest in the project.

## Validity checks passed

- **Window identical to run.010a:** 196 w5 files, 564,480 rows → 513,447 valid samples, 32.7 d (07-14 → 08-15), schema-5 100%, 76/76 features kept. Sanity anchor holds (lup_18 0.43% / ldn_18 0.36%).
- **Signal reproduces run.010a exactly** (same data, so it is a reproducibility check, not new evidence): daily-IC t h6 +7.75 / h18 +4.66, all 6 horizons significant, all 4 folds positive IC.
- **No-bias contract held:** the router was applied causally (walk-forward, val-only τ, refit scaler per step, starvation abstention), and when val found nothing it routed nothing. The honest answer, not a cherry-picked pass.

## The deeper finding: Cell 10D signal flipped sides and did not reproduce

| side | FILLED AUC | FAVOURABLE AUC |
|---|---|---|
| up18 (run.010a fired here: **0.610**) | 0.525 → chance | **0.518 → chance** |
| dn18 (was `nan` in run.010a) | 0.511 → chance | **0.613 → signal** |

Two things changed at once:

1. **The up18 0.610 that launched run.011 is gone** — now 0.518, squarely in the "~0.50 = chance" band. The dn-side pooled-OOF patch (the run.010a fix) re-computed the estimate cleanly, and the up-side "signal" turned out to be partly an averaging artifact over degenerate day-folds. It did not survive the honest re-estimate.
2. **What survives (dn18 0.613) is carried by regime/time proxies, not microstructure.** Top single features: `vol_ratio_1h_24h` 0.809, `lsr_z` 0.792, `ret_norm_4h` 0.774, `ma_gap_24h` 0.763, `minute_cos` 0.745 (up-side too: `dow_sin/cos`, `book_imbal_roll8/4`). Day-of-week / minute-of-day / rolling-window regime features dominating is exactly the profile that dies under walk-forward — and it did: the causal router, trained properly, found nothing to exploit.

## Interpretation & next steps

The notebook's own failure-mode read-out lists two branches; a third follows from the Cell 10D result:

1. **Starvation (most likely at 33 days):** only ~148/555 val triggers, so "no profitable τ on val" is weak evidence either way. The unbiased answer waits for the **≥45-day run (~Aug 28)**, reusing cell 10R unchanged. **Do not relax the no-bias contract.**
2. **The router genuinely can't separate fills causally** → sub-second order-flow is the last lever.
3. **(New) The premise itself is now shaky.** The 0.610 that fired the router branch did not reproduce, and what survives is dn-side + regime proxies. This *weakens* the "current features are enough" hypothesis and tilts the 45-day tiebreaker expectation toward **sub-second order-flow collection**, not the router.

**Bottom line:** ranking signal real and stable; economics still gated by fill mechanics; the causally-built router found nothing at 33 days. The ≥45-day run is the sole remaining decisive experiment.
